1. PROPÓSITO Y FUNCIÓN PRINCIPAL
================================================================================

OBJETIVO DE NEGOCIO
-------------------
La sección de asesores sirve como **punto de contacto humano** entre el 
prospecto y la empresa. Su función es:

- Humanizar la marca: Mostrar rostros reales del equipo de ventas
- Generar confianza: Presentar profesionales calificados que inspiran credibilidad
- Facilitar conversión: Cada tarjeta tiene un botón CTA que lleva al formulario
- Diferenciación competitiva: Destacar el equipo humano vs competidores que 
  solo muestran propiedades

MENSAJE CLAVE
-------------
"Contamos con un equipo de profesionales, altamente calificado y comprometido 
con el sueño de las familias panameñas de tener su propio hogar."

TONO EMOCIONAL: Cercanía, profesionalismo, compromiso con el cliente

3. SISTEMA DE CARRUSEL INFINITO
================================================================================

TECNOLOGÍA
----------
- JavaScript Vanilla (sin dependencias externas)
- Arquitectura: Clonación de slides para scroll infinito
- Animación: CSS transitions con cubic-bezier(0.4, 0, 0.2, 1)

MECÁNICA DE FUNCIONAMIENTO
--------------------------

3.1 CLONACIÓN DE TARJETAS
[Clones inicio] [Tarjetas originales] [Clones final]
     6 cards         6 cards             6 cards
   = 18 tarjetas totales en el DOM

Propósito: Cuando llegas al final, salta instantáneamente al inicio sin que 
el usuario lo note (scroll infinito seamless).

3.2 SISTEMA DE 3 ESTADOS
Las tarjetas tienen 3 posibles estados visuales:

┌─────────┬────────┬───────┬──────────┬────────┬────────────────┐
│ Estado  │ Clase  │ Ancho │ Opacidad │ Escala │ Sombra         │
├─────────┼────────┼───────┼──────────┼────────┼────────────────┤
│ Lateral │ .side  │ 260px │ 0.85     │ 0.92   │ Suave (0.08)   │
│ Centro  │.center │ 340px │ 1.0      │ 1.0    │ Prominente(0.2)│
│Inactiva │(ninguna)│ 260px│ 0.85     │ 0.92   │ Suave (0.08)   │
└─────────┴────────┴───────┴──────────┴────────┴────────────────┘

Efecto visual: La tarjeta central se "destaca" como si tuviera un spotlight,
atrayendo la atención.

3.3 AUTOPLAY INTELIGENTE
- Intervalo: 3 segundos (configurable en autoplayDelay)
- Pausa automática: 
  * Al hacer hover sobre el carrusel
  * Al hacer swipe en móvil
  * Cuando la sección NO está visible en viewport (IntersectionObserver)
- Reanudación: Al quitar hover o cuando vuelve a ser visible

Beneficio: Ahorra recursos de CPU/batería cuando el usuario no está viendo 
esta sección.

4. CONTROLES DE NAVEGACIÓN
================================================================================

4.1 BOTONES DE NAVEGACIÓN (DESKTOP)
-----------------------------------
Ubicación: Posición absoluta, laterales del carrusel
- Botón anterior (izquierda): Flecha ←
- Botón siguiente (derecha): Flecha →

Estilos:
- Fondo semi-transparente con backdrop-filter: blur(6px)
- Hover: Escala 1.1x + background más opaco
- Disabled state: Opacidad 0.3 (aunque en modo infinito nunca se desactivan)

4.2 INDICADORES PUNTEADOS (DOTS)
--------------------------------
Ubicación: Centrado, debajo del carrusel
- Cantidad: 6 dots (uno por asesor)
- Función: Navegación directa a cualquier asesor
- Estado activo: Más grande, color sólido, destaca con animación

4.3 THUMBNAILS LATERALES (OPCIONAL)
-----------------------------------
Estado actual: Código presente pero NO renderizado en HTML
- Concepto: Miniaturas verticales a la izquierda del carrusel
- Función: Vista previa + navegación rápida
- Tamaño: 64x64px con border-radius 12px

NOTA: Esta feature está desactivada en la implementación actual pero el 
código está listo para activarse agregando <div class="team__thumbs"></div> 
al HTML.

4.4 GESTOS TOUCH (MÓVIL/TABLET)
-------------------------------
- Swipe izquierda: Siguiente asesor
- Swipe derecha: Asesor anterior
- Threshold: 50px de desplazamiento mínimo para activar
- Feedback visual: Pausa autoplay durante interacción

================================================================================

BREAKPOINTS IMPLEMENTADOS
-------------------------

TABLET (769px - 1023px)
- Layout: Similar a desktop pero más compacto
- Cards: Todas 260px de ancho
- Botones: 48x48px
- Padding: 40px laterales

MOBILE (≤768px)
- Layout: Scroll horizontal, todas las cards iguales
- Cards: min(82vw, 270px) - se adapta al ancho de pantalla
- Fotos: Todas 130x165px (uniformes)
- Botones: Ocultos (solo swipe gestures)
- Thumbnails: Ocultos
- Estados: NO hay diferenciación center/side (todas iguales para legibilidad)

Filosofía móvil: Simplicidad > Complejidad. En pantallas pequeñas, todas las 
tarjetas tienen el mismo peso visual.

PALETA DE COLORES
-----------------
- Fondo tarjeta: #ffffff (blanco puro)
- Borde tarjeta: #e6e9ee (gris muy claro)
- Marco foto: rgba(0, 58, 122, 0.3) (azul corporativo semi-transparente)
- Texto nombre: #000000 (negro)
- Texto rol: #666666 (gris medio)
- Sombra tarjeta normal: 0 6px 16px rgba(0,0,0,0.08)
- Sombra tarjeta centro: 0 16px 48px rgba(0,0,0,0.2) ← Mucho más dramática

6.2 EFECTOS DE TRANSICIÓN
-------------------------

HOVER EN TARJETA
transform: translateY(-8px);  /* Levita hacia arriba */
box-shadow: 0 12px 40px rgba(0,0,0,0.15);  /* Sombra más fuerte */
Duración: 0.5s con easing suave

CAMBIO DE SLIDE
transition: transform 0.5s cubic-bezier(0.4, 0, 0.2, 1);
Easing personalizado: Aceleración suave al inicio, desaceleración al final 
(Material Design)

6.3 BOTÓN "CONSULTA"
--------------------
- Clase: .btn--secondary .btn--small
- Ancho: 100% (full-width en tarjeta)
- Padding: 0.6rem vertical, 1.5rem horizontal
- Función: Scroll suave a la sección #contacto (formulario)

7. PERFORMANCE Y OPTIMIZACIONES
================================================================================

7.1 IMÁGENES
------------
✓ Formato WebP: Reduce peso 25-35% vs JPEG
✓ Lazy Loading: loading="lazy" - solo carga al acercarse al viewport
✓ Dimensiones fijas: Evita layout shift (CLS)

Tamaños recomendados de imagen:
- Original: ~800x1000px
- Peso: <150KB por imagen
- Total sección: ~900KB (6 asesores)

7.2 JAVASCRIPT
--------------
✓ No dependencias externas: Bundle pequeño (~10KB minificado)
✓ IntersectionObserver: Pausa autoplay fuera de vista
✓ Debounce en resize: Evita cálculos excesivos al redimensionar
✓ RequestAnimationFrame: Para animaciones suaves sin jank

7.3 CSS
-------
✓ Hardware acceleration: transform en lugar de left/top
✓ Will-change: Implícito en transforms
✓ Backdrop-filter: Con fallback para navegadores antiguos

7.4 MÉTRICAS ACTUALES (ESTIMADAS)
---------------------------------
- LCP: ~2.5s (imagen héroe más grande)
- FID: <100ms (interacciones instantáneas)
- CLS: <0.1 (sin layout shifts si imágenes tienen dimensiones)

8. FUNCIONALIDAD DE NAVEGACIÓN
================================================================================

FLUJO DE INTERACCIÓN
--------------------
1. Usuario ve sección
2. Dispositivo Desktop → Ve 3 tarjetas (central destaca)
   Dispositivo Móvil → Ve 1 tarjeta completa
3. Autoplay cada 3s avanza automáticamente
4. Usuario puede:
   - Click en flechas (desktop)
   - Click en dots (todos)
   - Swipe (móvil/tablet)
   - Hover para pausar (desktop)
5. Si quiere contactar → Click CONSULTA
6. Scroll automático a formulario #contacto
7. Usuario completa formulario
8. Lead capturado

EVENTOS RASTREABLES (ANALYTICS)
-------------------------------
Eventos sugeridos para implementar:
1. carousel_autoplay_view - Asesor mostrado por autoplay
2. carousel_manual_navigation - Usuario usa botones/swipe
3. carousel_dot_click - Click en indicador
4. advisor_card_click - Click en botón CONSULTA
5. advisor_card_hover - Hover prolongado (>2s) en tarjeta

Datos a capturar:

- Método de navegación (autoplay, manual, swipe)
- Tiempo de permanencia en cada asesor
